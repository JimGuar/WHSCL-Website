Editing guide

Everything here is plain HTML and CSS. Change a file, save it, refresh the browser. No build step, no server, nothing to install.

1. Opening and editing 2. Which file holds what 3. Buttons 4. Section backgrounds and colour 5. Images and photos 6. Adding and removing sections 7. Text, headings and lists 8. Teams, competitions and registration 9. When something breaks 10. Publishing

1. Opening and editing

Double-click index.html to view the site. The address bar shows file:/// instead of https://, which is normal while you work on your own computer.

After saving a change, press Ctrl+Shift+R (Windows) or Cmd+Shift+R (Mac) in the browser. A plain refresh sometimes serves the old version from memory.

Use a real code editor rather than Notepad or TextEdit. VS Code is free, colours the code so mistakes stand out, and closes your tags for you.

Copy the folder before any big edit. Five seconds of insurance means no mistake is ever permanent.

2. Which file holds what

The .html files
Page layout
One per page. Headings, paragraphs, buttons, sections. This is what you edit to change how a page is arranged.
styles.css
All styling
Colours, spacing, typography. The colour variables sit at the very top.
The data-*.js files
Content lists
Teams, competitions, registration, resources. One file per area — see section 8.
The other .js files
Machinery
main.js, teams.js, season.js, resources.js. You should not need to touch these.

3. Buttons

Every button on the site is a link with a class on it. There is no separate button system to learn.

The three styles

<a class="button" href="teams.html">Find your team</a>
<a class="button button--light" href="season.html">Explore the season</a>
<a class="button button--outline" href="about.html">Learn more</a>

button is solid red, button--light is white, button--outline is transparent with a border. Use the light or outline versions on dark backgrounds. Add button--small for a compact one.

Adding a button

Buttons live inside a <div class="actions">, which handles spacing and wraps them onto separate lines on a phone. To add one, put another link inside that div:

<div class="actions">
  <a class="button" href="teams.html">Find your team</a>
  <a class="button button--outline" href="registration.html">Register</a>
</div>

If there is no actions div where you want the button, add the whole block.

Removing a button

Delete the entire <a ...>...</a> line. If it was the only button, delete the surrounding actions div too.

Where a button points

  • Another page here: href="season.html"
  • A spot on a page: href="season.html#hangouts"
  • An outside site: href="https://example.com" — add rel="noopener" too
  • An email: href="mailto:lizzy@adventurerock.com"
  • A phone number: href="tel:+12627906800"
  • A file in this folder: href="WHSCL-Handbook.pdf"

Registration buttons are different. The buttons on the Registration page come from data-registration.js, and the Hangout sign-up button from data-season.js. Neither is written in the HTML. See section 8.

4. Section backgrounds and colour

The site alternates between light and dark bands. You do not pick colours — you pick one of three section types, which keeps everything consistent.

<section class="section">                <!-- white -->
<section class="section section--soft">  <!-- light grey -->
<section class="section section--dark">  <!-- near-black -->

To change a band's colour, add or remove section--soft or section--dark. Nothing else needs changing: text inside a dark section turns white automatically.

One thing to remember on dark sections

Swap solid red buttons for button--light or button--outline, or they get lost against the dark background.

Changing the actual colours

The brand colours are defined once at the top of styles.css. Change them there and they update everywhere:

:root {
  --red: #c9202f;      /* buttons, accents, eyebrow labels */
  --ink: #111315;      /* dark sections, body text */
  --soft: #f4f5f6;     /* light grey sections */
}

--red is the WHSCL red sampled from the logo. Changing that one line restyles every button and accent on the site at once.

5. Images and photos

Adding an image to a page

Drop the file into this folder, then reference it by exact file name:

<img src="state-finals-2026.jpg"
     alt="Climber topping out at State Finals"
     width="1600" height="1067" loading="lazy">
  • alt describes the picture for screen readers and shows if the image fails to load. Always write one. Leave it empty (alt="") only for pure decoration.
  • width and height are the image's real pixel dimensions. They stop the page jumping about as images load.
  • loading="lazy" means the browser only fetches it when it scrolls into view.

If you set width and height, never set only the CSS width. That is exactly what stretched the footer logo into a tall smear. The stylesheet now carries img { height: auto; } which prevents it — do not remove that line.

File formats

Use JPG for photographs and PNG for logos and anything needing transparency.

HEIC will not work. iPhones save photos as .HEIC, which most browsers cannot display — the picture simply never appears. On a Mac, open it in Preview and choose File → Export, then pick JPEG. On Windows, open it in Photos and use Save as. To stop it at the source: on the iPhone, Settings → Camera → Formats → Most Compatible.

Size them before adding

A photo straight off a phone is often 4–8 MB, which makes the page crawl on mobile data. Resize to about 1600px on the long edge and save at roughly 80% quality. That usually lands under 400 KB with no visible difference.

Coach photos

These go in data-teams.js, not in the HTML. Put the file in this folder and write its exact name in the coach's photo field. Square images look best. If the file is missing, misspelled, or in a format the browser cannot read, the site falls back to the coach's initials in a circle rather than showing a broken image.

A photo as a section background

<section class="section section--dark"
  style="background-image:linear-gradient(rgba(17,19,21,.75),rgba(17,19,21,.75)),url('team-photo.jpg');
         background-size:cover; background-position:center;">

The dark gradient layered over the photo is what keeps the text readable. Without it, white text on a bright photo becomes unreadable.

6. Adding and removing sections

Every band down a page follows the same shape:

<section class="section">
  <div class="container">
    <p class="eyebrow">Small red label</p>
    <h2>The big heading</h2>
    <p class="lead">An intro sentence in larger grey text.</p>
  </div>
</section>

Copy that block, paste it where you want it, and change the words. container is what keeps content off the screen edges — always keep it.

Two columns

split puts a heading beside supporting content and collapses to one column on a phone automatically:

<div class="container split">
  <div> ...left... </div>
  <div> ...right... </div>
</div>

Cards

<div class="cards">
  <article class="card card--accent">
    <h3>Card heading</h3>
    <p>Card text.</p>
  </article>
</div>

cards makes the responsive grid, card is each box, and card--accent adds the red top edge.

Removing a section

Delete from <section through its matching </section>. In VS Code, click the small arrow in the margin beside the opening tag to collapse the whole block first — then you can see exactly what you are about to delete.

7. Text, headings and lists

Ordinary paragraphs are just <p>text</p>. Add class="lead" for the larger grey intro style.

Headings run h1 through h4 and should not skip levels — an h2 followed by an h4 confuses screen readers. One h1 per page.

Bold is <strong>, italic is <em>. A line break is <br>, though a new paragraph is usually better.

Special characters

  • &amp; gives & — always use this instead of a bare ampersand
  • &rsquo; gives an apostrophe ’ and &mdash; gives a long dash —
  • &ndash; gives the shorter dash – used in date ranges

The label above a heading

<p class="eyebrow"> is the small red uppercase label. It draws its own short line automatically — do not add one.

8. Teams, competitions and registration

These are lists rather than layout, so they live in the four data- files — one per area of the site. Each opens with instructions and a copy-paste template.

data-teams.js
Teams page
Teams, coaches, gyms, practice days and times.
data-season.js
Season page
Competitions, Hangouts, important dates, divisions, competition day schedule, past results, and the Hangout sign-up link.
data-registration.js
Registration page
The whole page: heading text, the league fee headline, every sign-up button, the fee table, and the help box.
data-resources.js
Resources page
Documents and links.

The rules are the same in all three: text in "double quotes", a comma at the end of every line, "" for anything blank, and straight quotes only.

Turning on a registration button

Open data-registration.js, find WHSCL_REGISTRATION_GROUPS, and paste the sign-up address between the quotes:

{ label: "Brookfield League Fee", url: "https://..." },

That is the whole job. A button with an empty url shows greyed out reading “link coming,” so an unfinished link never looks clickable.

Adding a sign-up location

Copy a button line inside the group it belongs to and change the label. To add a whole new box on the page — a new region, say — copy one of the group blocks and change its heading, paragraph and buttons:

{
  heading: "Teams practising at Greater Heights",
  intro: "One sentence explaining who this is for.",
  buttons: [
    { label: "Madison League Fee", url: "" },
  ],
},

Groups appear on the page in the order they are written. Changing a fee is in the same file, under WHSCL_FEES.

The Hangout sign-up button

That one is on the Season page, so it lives in data-season.js beside the Hangout dates. Paste the Adventure Rock booking address into WHSCL_HANGOUT_LINK. One button covers every Hangout. Leave it empty and it stays greyed out.

Instagram

Either form works — "@lyceumma" and "https://www.instagram.com/lyceumma/" both produce a working link.

9. When something breaks

Almost every problem is one of three things.

  1. A section vanished, or a grey “could not load” box appeared. A missing comma or quote in a data- file. Undo (Ctrl+Z / Cmd+Z), save, refresh.
  2. The layout collapsed below the point you edited. An unclosed tag. Check every <div> and <section> you added has a matching closing tag.
  3. An image shows as a broken icon. The file name does not match exactly — capitalisation counts — or it is a HEIC.

To see the actual error, press F12 (or right-click → Inspect) and open the Console tab. It names the file and the line number.

Check your work on a phone

Press F12, then click the small phone icon at the top of the panel. Pick a device or set the width to 390px. The whole site is designed mobile-first, so if it works at 390px it works anywhere. Watch for anything that scrolls sideways — that always means something is too wide.

10. Publishing

The site is a plain folder, so nearly any host works.

  • Netlify Drop (app.netlify.com/drop) — drag the folder onto the page and it is live in seconds. Drag it again to update.
  • GitHub Pages — more setup, but keeps a history of every version and lets several people help.

Rename _gitignore to .gitignore if you use GitHub. If you use Netlify Drop, ignore it.

Delete this guide file before publishing if you would rather it not be reachable, though nobody will find it unless you link to it.
